    Running TurtleVerse¶

    This guide assumes you've completed all installation steps. You'll need four or more terminal windows plus the Unity editor.

    Step 1 — Start the MQTT Broker¶

    Open a terminal and start Mosquitto:

    /opt/homebrew/opt/mosquitto/sbin/mosquitto -c /opt/homebrew/etc/mosquitto/mosquitto.conf

    Or, if you set it up as a background service:

    brew services start mosquitto

    Keep the broker running

    The MQTT broker must stay running for the entire session. Every component — Qualisys bridge, Unity, fleet bridge, commander — communicates through it.

    Step 2 — Connect to the Qualisys Network¶

    Ensure your Mac is on the same Wi-Fi network as the Qualisys MoCap PC. The QTM software must be running on the MoCap PC with the rigid bodies (TurtleBots) defined and streaming.

    QTM IP Address

    The default IP in run_qtm.py is 192.168.0.126. If your Qualisys PC has a different IP, update the QTM_PC_IP variable in the script before running.

    Step 3 — Stream Qualisys Poses¶

    Open a new terminal and run the Qualisys-to-MQTT bridge:

    python3 run_qtm.py

    You should see output like:

    MQTT Connected!
Bridging Standardized Poses to MQTT (Meters & Radians)...

Published -> turtle_verse/robot1/pose : {'x': 1.2345, 'y': 0.6789, 'theta': 1.5708}
Published -> turtle_verse/robot2/pose : {'x': 0.8012, 'y': 1.3456, 'theta': -0.7854}
...

    This script continuously reads 6-DOF rigid body data from QTM, converts positions from millimetres to metres, extracts yaw from the rotation matrix, and publishes to turtle_verse/robotN/pose.

    Step 4 — Start the ROS2 Fleet Bridge¶

    Open a new terminal, activate your ROS2 environment, and run the bridge:

    conda activate ros2humble
export ROS_DOMAIN_ID=<your_domain_id>
python3 mac_fleet_bridge.py

    You should see:

    Connecting to MQTT broker at 127.0.0.1...
Connected to Broker! Listening to ALL robots on: turtle_verse/+/cmd_vel

    Keep this running in the background

    The fleet bridge must stay running. It subscribes to MQTT velocity commands (turtle_verse/{robot}/cmd_vel) and dynamically creates ROS2 publishers for each robot it discovers. When a new robot name appears in the MQTT topics, it automatically creates a /robot_name/cmd_vel ROS2 publisher.

    TurtleBots Must Be Running

    Make sure each TurtleBot3 is powered on and running its ROS2 bringup (either via SSH or auto-boot). They must be on the same Wi-Fi and the same ROS_DOMAIN_ID.

    Step 5 — Launch Unity¶

    1. Open the TurtleVerse Unity project in Unity Hub.
    2. Open the main scene.
    3. Press Play (▶).

    Unity will connect to the MQTT broker and:

    • RealRobotTracker objects will mirror the physical TurtleBot poses from Qualisys.
    • SimulatedBurger objects will listen for cmd_vel commands and simulate digital-twin robots.

    Unity MQTT Configuration

    Each robot GameObject in the Unity scene has a brokerIP field in the Inspector. Set this to 127.0.0.1 if the broker is running locally on your Mac.

    Step 6 — Run a Swarm Commander¶

    Open a new terminal and launch one of the swarm control scripts:

    python3 commander_square.py

    The leader (robot1) follows a square path through predefined waypoints. All other robots in the chain follow in sequence using pure pursuit.

    python3 SwarmCommander.py

    All robots form a closed pursuit ring — each agent chases the next in a circular topology.

    Both scripts include a 5-second safety countdown before engaging the swarm:

    Swarm engaging in 5 seconds... (Press Ctrl+C to abort)
Swarm engaging in 4 seconds... (Press Ctrl+C to abort)
...
🚀 GO! 🚀

    Safety

    Always be ready to press Ctrl+C to stop the commander. This sends zero-velocity commands to all robots before shutting down.

    Summary: What Should Be Running¶

    Terminal / App What's Running Status
    Terminal 1 mosquitto broker Running (keep open)
    Terminal 2 run_qtm.py (Qualisys → MQTT) Streaming poses
    Terminal 3 mac_fleet_bridge.py (MQTT → ROS2) Bridging commands
    Terminal 4 SwarmCommander.py or commander_square.py Controlling swarm
    Unity Editor TurtleVerse simulation Playing

    Troubleshooting Quick Fixes¶

    Problem Fix
    run_qtm.py won't connect Verify Mac is on the same Wi-Fi as the Qualisys PC; check QTM_PC_IP
    No pose data in Unity Verify run_qtm.py is printing poses; check MQTT with mosquitto_sub -h 127.0.0.1 -t "turtle_verse/#" -v
    TurtleBots don't move Check mac_fleet_bridge.py is running; verify ROS_DOMAIN_ID matches; confirm TurtleBot bringup is active
    Unity robots jitter This is normal at high update rates — RealRobotTracker applies Lerp smoothing. Ensure QTM is tracking markers cleanly
    "Connection refused" Make sure the MQTT broker is running on port 1883
    Commander crashes immediately Ensure paho-mqtt is installed (pip3 install paho-mqtt)
