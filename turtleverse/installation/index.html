    TurtleVerse Installation¶

    This page covers everything you need to install before running TurtleVerse. The setup consists of four parts:

    Step What Time
    1 Unity Project — Clone the TurtleVerse Unity project ~15 min
    2 MQTT Broker — Same Mosquitto setup as SparkVerse ~5 min
    3 Qualisys Python Bridge — Install dependencies for run_qtm.py ~5 min
    4 ROS2 Humble (RoboStack) — Required for mac_fleet_bridge.py ~15 min
    5 Swarm Commander Dependencies — Python packages for the control scripts ~2 min

    Platform

    This guide is written for macOS on Apple Silicon (M1 / M2 / M3 / M4). The TurtleBots run ROS2 Humble on their onboard Raspberry Pi.

    1. Unity Project¶

    The TurtleVerse Unity project is separate from the SparkVerse Unity project. It contains the TurtleBot3-specific prefabs, scenes, and C# scripts (RealRobotTracker.cs, SimulatedBurger.cs, MqttPayloads.cs).

    Repository — Coming Soon

    The TurtleVerse Unity project GitHub repository is not yet public. This section will be updated with the clone URL once it is available.

    Once the repository is available:

    1. Install Unity Hub and Unity 6.3 LTS (6000.3.2f1) — same version as SparkVerse. See the SparkVerse Unity Setup for detailed steps.
    2. Clone the TurtleVerse repository.
    3. Open the project in Unity Hub.

    2. MQTT Broker¶

    TurtleVerse uses the same Mosquitto MQTT broker as SparkVerse. If you've already set it up, you're good to go.

    If not, follow the MQTT Broker Setup guide.

    3. Qualisys Python Bridge¶

    The run_qtm.py script connects to the Qualisys Track Manager (QTM) software over the network, reads 6-DOF rigid body data, and publishes standardised poses to MQTT.

    Dependencies¶

    pip3 install qtm-rt paho-mqtt
    Package Purpose
    qtm-rt Async Python SDK for the Qualisys Real-Time protocol
    paho-mqtt MQTT client library for publishing poses to the broker

    Standard library modules used: asyncio, json, math.

    Verify¶

    python3 -c "import qtm_rt; import paho.mqtt.client; print('Qualisys bridge deps OK')"

    Network Requirement

    Your Mac must be on the same Wi-Fi network as the Qualisys MoCap PC. The default QTM IP in the script is 192.168.0.126 — update this to match your Qualisys PC's address.

    4. ROS2 Humble via RoboStack¶

    The mac_fleet_bridge.py script is a ROS2 node that subscribes to MQTT velocity commands and republishes them as ROS2 geometry_msgs/Twist messages for the TurtleBots. This requires a working ROS2 Humble installation on your Mac.

    The recommended approach for macOS is RoboStack — a conda-based distribution of ROS2. Follow the RoboStack installation guide to set up a ROS2 Humble conda environment on your Mac.

    ROS_DOMAIN_ID

    All devices (Mac and TurtleBots) must share the same ROS_DOMAIN_ID. Set it in every terminal before running ROS2 commands:

    export ROS_DOMAIN_ID=<your_domain_id>

    Replace <your_domain_id> with the ID your TurtleBots are configured to use.

    Dependencies for mac_fleet_bridge.py¶

    Package Source Purpose
    rclpy ROS2 Humble (via RoboStack) ROS2 Python client library
    geometry_msgs ROS2 Humble (via RoboStack) Twist message type for velocity commands
    paho-mqtt pip MQTT client for receiving commands from the broker

    TurtleBot3 Side Setup¶

    TurtleBot3 Preparation

    Each TurtleBot3 Burger runs ROS2 Humble on a Raspberry Pi. Before TurtleVerse can control them, the TurtleBots must be running their ROS2 bringup nodes.

    SSH into each TurtleBot and run:

    ssh ubuntu@<turtlebot_ip>
export ROS_DOMAIN_ID=<your_domain_id>
ros2 launch turtlebot3_bringup robot.launch.py

    This starts the motor controller and cmd_vel subscriber on the TurtleBot.

    To verify from your Mac (with the same ROS_DOMAIN_ID):

    ros2 topic list

    You should see topics like /robot1/cmd_vel, etc.

    Auto-Bringup on Boot

    You can configure each TurtleBot's Raspberry Pi to automatically run the bringup launch file on boot (e.g., via a systemd service). This way, you only need to power on the robots and ensure they connect to the same Wi-Fi — no SSH required during normal operation. All you need on your Mac is:

    export ROS_DOMAIN_ID=<your_domain_id>

    5. Swarm Commander Dependencies¶

    Both SwarmCommander.py and commander_square.py (which share the same codebase with different default configurations) require only:

    pip3 install paho-mqtt
    Package Purpose
    paho-mqtt MQTT client for subscribing to poses and publishing velocity commands

    Standard library modules used: json, time, math.

    Dependencies Summary¶

    Script Python Packages System Requirements
    run_qtm.py qtm-rt, paho-mqtt Same Wi-Fi as Qualisys PC
    mac_fleet_bridge.py paho-mqtt, rclpy, geometry_msgs ROS2 Humble (RoboStack)
    SwarmCommander.py paho-mqtt —
    commander_square.py paho-mqtt —

    What's Next¶

    All dependencies are installed. Continue to Running TurtleVerse to launch everything.
